# Contributing to Sorbus

## Reporting Issues

Found a bug or something not working as expected? Open an issue on GitHub and include:
- What you were doing
- What you expected to happen
- What actually happened
- Any relevant logs (check `server_output.txt` for C++ server logs)

## Contributing Code

1. Fork the repository
2. Create a branch for your change
3. Make your changes
4. Open a pull request describing what you changed and why

## Code Style

- Every function gets a one-line comment describing what it does. No multi-line comment blocks.
- Match the style of the surrounding code — your changes should look like they belong.
- Keep it minimal. Prefer the smallest change that solves the problem; avoid unnecessary abstractions, redundant code, and over-commenting.

## Using AI Tools

AI-assisted code is welcome — but it must be held to the same bar as anything else:

- **Review and test it thoroughly.** Don't open a PR with code you haven't run and verified actually works.
- **You must understand it.** Be able to explain how the change works and what each line does, and how it fits the rest of the project. If you can't explain it, don't submit it.
- **No fully "vibe-coded" PRs.** Code generated and pasted without understanding or testing will be rejected.
- **Follow the project's code style** (above). AI tends to produce verbose, over-abstracted code — trim it down to match the lean style of the existing codebase.

## Questions & Inquiries

For any questions, ideas, or general discussion, open a GitHub issue.

All contributions, bug reports, and communication should go through GitHub.
